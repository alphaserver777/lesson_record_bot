# ADR-001: Стратегия окружения разработки

## Статус

Принято

## Контекст

Проект разрабатывается на NixOS. Текущая настройка проекта опирается на `requirements.txt`, `miniapp/package.json` и Docker-based сценарии, но локальная разработка должна быть воспроизводимой и не зависеть от изменчивого состояния хоста.

## Решение

Использовать отдельный Nix dev shell как основное локальное окружение разработки для `lesson_record_bot`.

Dev shell должен предоставлять:
- Python для backend и bot-разработки
- Node.js для разработки Mini App
- SQLite tooling для локальной проверки данных
- Git и базовые инструменты сборки

Docker остаётся опциональным инструментом для deployment-oriented и изолированных сценариев, но не является основным локальным workflow.

## Последствия

- Локальный вход в проект на NixOS становится детерминированным.
- Версии Python и Node фиксируются через flake, а не через состояние хоста.
- Часть текущих README- или Docker-centric инструкций потребует последующего обновления.
