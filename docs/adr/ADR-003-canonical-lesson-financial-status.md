# ADR-003: Canonical lesson financial status

## Status

Accepted

## Context

Расписание хранит экземпляры занятий в `record_dates`, а финансовый журнал — в
`payments`. Исторически они сопоставлялись по Telegram ID, дате и времени.
Время является изменяемым атрибутом и не может быть идентификатором: занятие
можно перенести или повторно материализовать из регулярного шаблона.

## Decision

- канонический идентификатор экземпляра занятия — `record_dates.id`;
- финансовое решение хранится в `payments` и ссылается на занятие через
  `payments.lesson_id`;
- для одного существующего занятия допускается одно текущее финансовое решение;
- дата, время, имя и Telegram ID в `payments` временно сохраняются как
  compatibility snapshot для старых данных;
- предоплата не относится к конкретному занятию и имеет `lesson_id = NULL`;
- регулярный шаблон не является проведённым занятием: перед финансовым решением
  его occurrence материализуется в `record_dates`;
- legacy-поиск по времени разрешён только как fallback на период миграции.
- канонические строки занятий больше не удаляются фоновым семидневным cleanup.

## Consequences

Перенос времени больше не меняет идентичность занятия и не теряет оплату.
Удаление старого занятия оставляет финансовую историю благодаря `ON DELETE SET
NULL`. Миграция аддитивна, но новые записи должны использовать FK, а monitoring
должен выявлять новые lesson payments без `lesson_id`.
