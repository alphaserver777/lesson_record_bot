# Переезд прикладной БД в PostgreSQL

## Что переезжает

В PostgreSQL `proffessor_it` будут перенесены профили учеников, записи и регулярные занятия, оплаты, маркетинговые события, рабочее расписание и исключения. SQLite на Germany2 не удаляется и служит проверенной точкой отката.

Twenty CRM использует отдельную техническую БД. Обмен с ним будет происходить через API: CRM не получает прямой доступ к расписанию и оплатам.

## Безопасная последовательность

1. На `vm-robots-dev1` создать `/srv/proffessor-it/postgres/.env` по примеру `deploy/postgres/.env.example` и указать уникальный пароль.
2. Запустить `docker compose up -d` из этой папки и дождаться healthy PostgreSQL.
3. Скопировать SQLite-файл с Germany2 в закрытый временный каталог VM, не меняя исходник.
4. Запустить `scripts/migrate_sqlite_to_postgres.py` с `DATABASE_URL`. Скрипт допускает импорт только в пустую базу и сверяет количества строк.
5. Поднять копию API и бота с `DATABASE_URL`, провести проверку записи, оплаты и уведомления на тестовом аккаунте.
6. В согласованное окно переключить production-бот на новый URL БД. SQLite и прежние контейнеры не удалять до контрольного периода.

Нельзя направлять Twenty напрямую в базу `proffessor_it` и нельзя удалять SQLite до завершения контрольного периода.
