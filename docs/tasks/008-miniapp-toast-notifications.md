## Контекст

Сейчас Mini App использует примитивную текстовую обратную связь об ошибках и успехе действий. Сообщения визуально живут внизу интерфейса и воспринимаются как технический остаток состояния, а не как управляемая системная обратная связь.

Это создаёт проблемы:

- пользователь может не заметить результат действия
- успех и ошибка визуально не отличаются достаточно явно
- уведомления не соответствуют качеству UI Mini App
- текущий подход размазывает `success/error` state по большому `App.jsx`

На уровне UX проект уже просит отдельный notification-layer с iPhone-подобными всплывающими уведомлениями.

## Цель

Заменить текущую низкосигнальную текстовую обратную связь на единый слой toast/popup-уведомлений для Mini App, сохранив простую интеграцию с текущими flows.

## Scope

В scope:

- ввести единый notification/toast layer для Mini App
- поддержать как минимум типы `success`, `error`, `info`
- заменить текущие основные `setSuccess` / `setError` сообщения на новый UI feedback
- добавить аккуратную анимацию появления/скрытия
- сделать уведомления заметными, но не навязчивыми

Вне scope:

- полный frontend-рефактор всего Mini App
- переработка бизнес-логики форм
- сложная очередь уведомлений с приоритетами и action buttons

## Ограничения

- Новая система не должна ломать текущие flows.
- Ошибки API должны оставаться читаемыми и не теряться.
- Нельзя превращать уведомления в модальные окна для обычных success/error-сценариев.
- Реализация должна быть достаточно локальной, чтобы не смешать её с большим архитектурным рефакторингом фронтенда.

## Текущее состояние

- `App.jsx` хранит и рендерит успех/ошибку как часть общего state.
- Уведомления расположены неудачно и слабо встроены в визуальный язык приложения.

## Предлагаемое изменение

### 1. Новый notification layer

Добавить отдельный компонент или слой, например:

- `ToastHost`
- `useToast`

С контрактом вида:

- `showToast({ type, title, message })`

### 2. Визуальное поведение

Целевой стиль:

- ближе к iOS-style popup/toast
- верхняя или центральная безопасная зона
- blur/backdrop
- мягкая тень
- короткая fade/slide анимация
- auto-dismiss для обычных success/info
- более заметное поведение для error

### 3. Интеграция

Сначала перевести на новый слой самые частые сценарии:

- создание/удаление брони
- добавление временных слотов
- назначение клиента на слот
- ошибки API

## Затронутые области

- `miniapp/src/App.jsx`
- возможно новые frontend-компоненты и hooks
- возможно `miniapp/src/styles.css`

## Acceptance Criteria

- Успешные действия показывают заметный и аккуратный popup/toast.
- Ошибки показываются через тот же единый слой, но визуально отличаются от success.
- Основные admin/user сценарии больше не опираются на нижний текстовый блок как основной feedback.
- Реализация не ухудшает текущую работоспособность Mini App.

## Verification

- Проверить success toast на create/delete действиях.
- Проверить error toast на предсказуемой API-ошибке.
- Проверить, что уведомления закрываются корректно и не залипают.
- Собрать Mini App.

## Rollback / Safety

- Изменение должно быть локальным для frontend.
- Если новый notification-layer вносит регрессии, можно быстро вернуть старый рендеринг success/error.

## Заметки

- Это задача на UX и UI-feedback, а не на архитектурное разбиение всего фронтенда.
- Текущая реализация оставляет существующий `setSuccess` / `setError` state, но переводит его на единый floating toast-layer.
- Inline contextual `.toast` не удалён полностью и может оставаться для локальных предупреждений внутри конкретной карточки.
