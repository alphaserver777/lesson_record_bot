## Контекст

В admin Mini App переключение месяца в календаре может занимать несколько секунд.
Причина в том, что month endpoint пересчитывает доступность по дням последовательно и для каждого дня отдельно вызывает тяжёлый расчёт свободных слотов.

Дополнительно в режиме `Свободные слоты` календарь должен ясно показывать дни без доступных окон:

- полностью занятые дни не должны выглядеть как активные
- админ не должен тратить лишний клик на день, где свободных слотов всё равно нет

## Цель

Ускорить загрузку месяца в admin-календаре без потери рабочего UX:

- month summary должен считаться заметно дешевле
- в режиме `Свободные слоты` дни без доступных окон должны быть визуально неактивны
- точный список свободных времен должен по-прежнему рассчитываться только для выбранного дня

## Scope

В scope:

- оптимизация backend endpoint `/api/admin/schedule/month`
- пакетный расчёт `booked_count/free_count/has_free` на месяц
- обновление admin calendar UI для неактивного состояния полностью занятых дней в режиме `Свободные слоты`

Вне scope:

- полный redesign admin calendar
- изменение user calendar
- изменение бизнес-правил расписания и записи

## Ограничения

- сохранить существующий API-контракт month endpoint
- не ломать admin flows `Записанные` и `Бронь`
- точный расчёт свободных времен для выбранного дня должен остаться в day-level endpoint

## Текущее состояние

Сейчас admin month endpoint проходит по каждому дню месяца и для будущих дней отдельно вызывает полный расчёт доступных слотов.
Это даёт заметную задержку на SQLite и делает month switch тяжёлым.

## Предлагаемое изменение

1. Считать month summary пакетно:
   - одним чтением записей месяца
   - одним чтением регулярных занятий нужных weekday
   - одним чтением skip exceptions месяца
2. Для каждого дня строить:
   - `booked_count`
   - `free_count`
   - `has_booked`
   - `has_free`
   - `past`
3. Во frontend в режиме `Свободные слоты` делать дни с `has_free=false` визуально неактивными и disabled.

## Acceptance Criteria

- Переключение месяца в admin-календаре выполняется заметно быстрее, чем прежний последовательный расчёт по дням.
- В режиме `Свободные слоты` дни без доступных слотов отображаются как неактивные.
- Для полностью занятых дней в режиме `Свободные слоты` нельзя нажать кнопку дня.
- В режимах `Записанные` и `Бронь` календарь продолжает работать как раньше.

## Rollback / Safety

- Rollback ограничивается admin month summary и admin calendar UI.
- В случае отката можно вернуть прежний month endpoint без изменения day-level endpoint для точных слотов.

## Заметки

- Реализация выполнена через пакетный расчёт month summary на backend.
- Точный список слотов не переносится в month response и остаётся day-level расчётом.
