# Task: reliable-cicd

## Status

Done

## Контекст

Проверки ключевых потоков записи и оплаты уже запускаются в GitHub Actions, но
нет единого барьера для качества кода, сборки кабинета, проверки зависимостей и
контролируемого развёртывания. Ручной запуск допускает ошибочный каталог или
фиксацию.

## Цель

Сделать поставку воспроизводимой: изменения проходят обязательные проверки,
выпуск создаётся только из `main` аннотированной меткой, а развёртывание
запускается вручную только по этой метке, с резервной копией PostgreSQL и
проверками после запуска.

## Scope

В scope:

- проверки Python, Ansible, критических бизнес-сценариев, сборки кабинета и
  зависимостей;
- проверка отсутствия типовых секретов в отслеживаемых файлах;
- сценарии GitHub Actions для создания выпуска и рабочего развёртывания;
- проверка соответствия исходников аннотированной метке;
- резервная копия и автоматический возврат к предыдущему каталогу при ошибке
  развёртывания;
- документация и настройки, которые владелец должен включить в GitHub.

Вне scope:

- передача секретов в Git;
- автоматическое развёртывание каждой фиксации;
- изменение данных PostgreSQL или автоматическое восстановление базы.

## Acceptance Criteria

- изменения в `main` и `develop` не проходят без всех обязательных проверок;
- выпускная метка создаётся только для текущей фиксации `main`;
- рабочее развёртывание принимает только аннотированную метку, достижимую из
  `main`;
- перед переключением версии успешно создаётся проверяемая копия PostgreSQL;
- при ошибке запуска или проверки ссылка `current` возвращается на предыдущий
  выпуск без отката данных;
- закрытый ключ и отпечаток сервера задаются только в защищённых секретах GitHub.

## Verification

- `python3 scripts/verify_cicd_source.py`;
- `python3 scripts/verify_release_source.py --tag <метка> --commit <SHA> --require-main`;
- `cd infra/ansible && ansible-playbook --syntax-check deploy.yml`;
- `./scripts/test_critical_flows.sh`;
- успешные проверки GitHub Actions на `develop` и `main`.

## Rollback / Safety

Сценарий развёртывания сохраняет предыдущую ссылку `current`. При ошибке
контейнеров или маршрутов он возвращает ссылку и повторно запускает предыдущий
закреплённый выпуск. PostgreSQL не восстанавливается автоматически.

## Заметки

Владелец GitHub должен включить обязательные проверки веток и задать защищённые
окружения `release` и `production`; это нельзя безопасно сделать фиксацией кода.

При первом запуске конвейер обнаружил высокие уязвимости в `Pillow==10.4.0`.
Версия закреплена на `12.3.0`, содержащей исправления.

Следующая проверка обнаружила уязвимости в устаревшей транзитивной версии
`aiohttp`, ограниченной старым `aiogram`. Обновлены `aiogram`, `aiohttp` и
`aiohttp-socks`; создание клиентов приведено к актуальному интерфейсу
`DefaultBotProperties`.

Последняя проверка зависимостей также выявила исправленные уязвимости в
`python-dotenv` и `python-multipart`. Они закреплены на версиях `1.2.3` и
`0.0.32` соответственно.

После этого аудит выявил транзитивный `starlette==0.41.3`, ограниченный старым
`fastapi`. Обе зависимости обновлены до совместимых версий `0.141.1` и
`1.6.0`; `starlette` закреплён явно, чтобы проверяемая версия не менялась
неявно.

В `miniapp` пока отсутствует зафиксированный `package-lock.json`, поэтому
сборка использует `npm install`. Конвейер проверяет саму сборку и аудит
зависимостей, но полная фиксация транзитивных версий требует отдельной задачи:
создать lock-файл в доверенной сетевой среде, проверить его и заменить
`npm install` на `npm ci` также в Dockerfile.
