## Контекст

Сейчас в системе есть несколько потоков напоминаний:

- запрос подтверждения присутствия на день занятия
- напоминание за 60 минут до начала
- напоминание за 10 минут до начала

По коду уже видно расхождение:

- при разовой отмене регулярки через `regular_lesson_exceptions.skip` напоминания должны подавляться корректно
- при отмене занятия через admin block с `block_and_cancel_notify` краткосрочные reminders могут продолжать уходить, потому что `records_starting_at(...)` уважает `skip` и legacy `allow`, но не подавляет слоты, перекрытые `block`
- текущий админский reminder за 10/60 минут слишком бедный: не хватает явного типа занятия, стоимости, информации о последнем занятии с учеником и другого контекста, полезного для быстрой подготовки к уроку

## Цель

Сделать поведение reminders доменно корректным после отмен и блокировок, а также сделать админское напоминание за 10 минут информативным и пригодным для оперативной работы.

## Scope

В scope:

- исправить подавление reminders для отменённых и заблокированных слотов
- убедиться, что presence prompt, reminder за 60 минут и reminder за 10 минут не уходят по отменённому занятию
- исправить сценарий block cancellation так, чтобы для регулярного занятия создавалось корректное исключение на дату
- обогатить админское напоминание за 10 минут данными о занятии и ученике
- при необходимости выровнять `records_starting_at(...)` и другие функции-источники reminders с доменной моделью слотов
- задокументировать итоговое поведение reminders

Вне scope:

- полная переработка всей reminder-системы
- изменение пользовательского текста всех уведомлений вне нужных сценариев
- новая аналитика посещаемости
- изменение UI Mini App

## Ограничения

- Нельзя сломать уже работающие reminders для реальных занятий.
- Нельзя вернуть повторную рассылку по одному и тому же слоту из-за дубликатов записей.
- Нельзя сломать single bookings, regular lessons, admin blocks и `regular_lesson_exceptions`.
- Логика подавления reminders должна быть одинаково корректной для разовых и регулярных занятий.
- Формат админского reminder должен оставаться компактным и читаемым в Telegram.

## Текущее состояние

- `pending_presence_for_date(...)` подавляет materialization регулярки в слоты, перекрытые `block/allow`, и учитывает `skip`.
- `records_starting_at(...)` для краткосрочных reminders учитывает `skip` и legacy `allow`, но не подавляет `block`.
- В `block_and_cancel_notify` при конфликте с regular lesson не создаётся явное исключение регулярки на дату; фактически ставка идёт на блок поверх слота.
- Текущее сообщение админу перед началом занятия содержит только имя, время, телефон и ссылку на пользователя.

## Предлагаемое изменение

### 1. Единое подавление reminders

Нужно привести источники reminders к одному правилу:

- если занятие отменено разово, reminders не уходят
- если слот перекрыт админским блоком и занятие отменено в рамках block flow, reminders не уходят
- если regular lesson отменён на конкретную дату, это должно выражаться явным `skip`, а не только удалением materialized записи

### 2. Корректная обработка block-and-cancel для регулярки

Если admin block пересекается с regular lesson и выбран сценарий `block_and_cancel_notify`:

- на эту дату должен создаваться `regular_lesson_exceptions.skip`
- существующая materialized запись на эту дату должна удаляться, если она уже есть
- после этого никакие reminders по этому слоту больше не должны уходить

### 3. Обогащение admin reminder за 10 минут

Админу за 10 минут до начала занятия должно приходить сообщение с полезным контекстом, как минимум:

- имя ученика
- время занятия
- тип занятия: `регулярное` / `разовое`
- длительность
- стоимость занятия
- телефон
- когда было крайнее занятие с этим учеником
- ссылка `tg://user`

Если часть данных отсутствует, сообщение должно деградировать безопасно, без падения и без “None” в тексте.

### 4. Приоритет

Первый приоритет:

- не слать reminders по отменённым/заблокированным слотам

Второй приоритет:

- улучшить качество admin reminder за 10 минут

## Acceptance Criteria

- После разовой отмены regular lesson reminders по этой дате не уходят.
- После admin block с отменой занятия reminders по пересечённому слоту не уходят.
- `records_starting_at(...)` и смежные источники reminders не возвращают слоты, подавленные block/skip/allow по доменным правилам.
- Админ за 10 минут до начала получает reminder с типом занятия, стоимостью, длительностью и датой последнего занятия с учеником.
- Если часть данных недоступна, reminder всё равно отправляется в корректном виде.
- Single и regular reminders для реально существующих занятий продолжают работать.

## Заметки

- Если в ходе реализации выяснится, что для admin reminder полезны ещё баланс занятий или заметки по ученику, это можно выделить в follow-up, но не перегружать первое сообщение.
- Краткосрочные reminders теперь используют общий источник `records_starting_at_details(...)`, который подавляет regular templates в слотах, перекрытых `block`, `skip` и legacy `allow`.
- В сценарии `block_and_cancel_notify` для regular lesson теперь создаётся корректное исключение на дату через `cancel_regular_occurrence(...)`, а не только ставится блок поверх слота.
