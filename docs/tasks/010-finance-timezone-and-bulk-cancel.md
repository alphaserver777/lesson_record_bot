## Контекст

Во вкладке `Управление -> Финансы` есть раздел `Незакрытые занятия`, где администратор после фактического времени урока должен принять решение:

- `Оплачено`
- `В долг`
- `Отмена`

Сейчас выявлены две проблемы:

1. В production Mini App API flow для `unclosed lessons` опирается на `get_calendar_tz()`, но `CALENDAR_TIMEZONE` на `Germany2` не задан, поэтому backend фактически живёт в `UTC`. Из-за этого прошедший по Москве урок не попадает в список “незакрытых” сразу после своего времени по МСК.
2. В массовых действиях по чекбоксам доступны только:
   - `Массово: Оплачено`
   - `Массово: В долг`
   но нет `Массово: Отмена`.

## Цель

Сделать раздел `Незакрытые занятия` корректным по московскому времени и завершить его как рабочий admin-инструмент с полным набором массовых решений.

## Scope

В scope:

- зафиксировать корректную timezone-настройку для finance/unclosed flow
- убедиться, что production использует `Europe/Moscow` для календарных расчётов Mini App API
- исправить попадание прошедших занятий в `Незакрытые занятия` сразу после наступления времени урока по Москве
- добавить массовое действие `Массово: Отмена`
- проверить мобильное отображение блока массовых действий
- отразить итог в документации

Вне scope:

- переработка всей финансовой модели
- изменение статусов платежей
- редизайн всего раздела `Финансы`
- перенос finance flow в Telegram-бот

## Ограничения

- Нельзя сломать уже работающие решения `Оплачено` и `В долг`.
- Нельзя ломать расчёт reminder/time-based flows, которые используют ту же timezone-конфигурацию.
- Изменение production env должно быть явным и документированным.
- Массовая отмена должна использовать ту же доменную модель, что и одиночная отмена, а не отдельный обходной путь.

## Текущее состояние

- `GET /api/admin/lessons/unclosed` использует `datetime.datetime.now(get_calendar_tz())`
- `get_calendar_tz()` использует `CALENDAR_TIMEZONE` или падает в `UTC`
- на `Germany2` переменная `CALENDAR_TIMEZONE` для Mini App API сейчас не задана
- в UI есть массовые действия только для `paid` и `unpaid`

## Предлагаемое изменение

### 1. Timezone для production

Явно задать и зафиксировать `CALENDAR_TIMEZONE=Europe/Moscow` для production stack, чтобы:

- `Незакрытые занятия`
- presence/reminder flows
- другие time-based проверки расписания

работали в одной бизнес-зоне времени.

### 2. Корректное попадание урока в unclosed flow

После наступления времени урока по Москве запись должна появляться в `Незакрытые занятия`, если по ней ещё не принято решение и нет payment-записи.

### 3. Bulk cancel

В блоке массовых действий добавить кнопку:

- `Массово: Отмена`

которая отправляет `decision="canceled"` через уже существующий bulk flow.

### 4. Мобильный UX

Если три массовые кнопки не помещаются в текущий layout, нужно адаптировать сетку/перенос строк так, чтобы все действия были видимы и нажимаемы на мобильном экране.

## Заметки

- Это не просто визуальный фикс: timezone здесь влияет на бизнес-момент “урок уже прошёл или ещё нет”.
- После этого шага имеет смысл отдельно проверить и reminder flow на предмет консистентности с новой production timezone.

## Результат

- Flow `Управление -> Финансы -> Незакрытые занятия` теперь должен оценивать “урок уже прошёл” по московскому времени, а не по `UTC`.
- В bulk actions добавлена кнопка `Массово: Отмена`.
- Для строки массовых действий добавлен мобильный wrap-layout, чтобы все три решения были видимы на узком экране.
