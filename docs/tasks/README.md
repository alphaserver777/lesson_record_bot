# Спецификации Задач

Каждое содержательное изменение должно начинаться с task spec в этом каталоге.

## Именование

Используйте сортируемые имена, например:

- `001-miniapp-auth-hardening.md`
- `002-booking-source-of-truth.md`
- `003-admin-approval-cleanup.md`

## Процесс

1. Создать новый файл задачи на основе `TEMPLATE.md`.
2. Заполнить scope, constraints, acceptance criteria и verification до начала реализации.
3. Держать реализацию внутри заявленного scope.
4. Если задача меняет архитектуру или долгоживущие правила, добавить или обновить ADR.
5. Когда задача завершена, перевести `Status` из `Proposed` в `Done` и оставить спецификацию как историю решения.

## Правило

Если изменение нельзя описать достаточно ясно в рамках шаблона, значит оно ещё не готово к реализации.
