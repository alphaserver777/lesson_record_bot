## Контекст

В Mini App при переключении месяца наблюдается два связанных дефекта:

- при выборе апреля UI может показывать свободные слоты, визуально похожие на мартовские
- в момент загрузки нет явного индикатора, поэтому пользователь не понимает, это stale данные, баг или просто ожидание ответа

По пользовательскому восприятию экран выглядит так, будто данные нового месяца не загрузились, а старое состояние осталось на месте.

## Цель

Сделать month switch в календаре корректным и прозрачным:

- данные должны соответствовать выбранному месяцу
- stale слоты не должны отображаться как финальный результат
- во время загрузки должен быть явный loading-state

## Scope

В scope:

- диагностика stale state при смене месяца
- исправление frontend state flow календаря
- при необходимости корректировка API-вызовов на загрузку календаря/слотов
- заметный loading indicator для month switch
- защита от race condition при быстром переключении месяцев

Вне scope:

- полный редизайн календаря
- изменение бизнес-правил расписания, если они не связаны с багом month switch

## Текущее состояние

Сейчас пользователь может:

- выбрать апрель
- увидеть картину доступности, похожую на март
- не получить визуального подтверждения, что данные ещё догружаются

Это может означать:

- stale frontend state
- отсутствие сброса старых данных при новом запросе
- race condition между запросами
- неполную реакцию UI на смену месяца

## Предлагаемое изменение

1. Привязать состояние календаря и слотов к актуально выбранному месяцу.
2. Не показывать результат предыдущего месяца как завершённый результат нового месяца.
3. Добавить явный loading-state:
   предпочтительно top loading bar, progress bar, skeleton или loading overlay.
4. Гарантировать, что при быстром переключении месяцев UI принимает только результат последнего актуального запроса.
5. Явно различать состояния:
   загрузка, пустой результат, ошибка.

## Acceptance Criteria

- При переключении с марта на апрель UI больше не показывает мартовские слоты как данные апреля.
- Во время загрузки нового месяца пользователь видит явный loading indicator.
- После загрузки отображаются либо корректные данные выбранного месяца, либо корректный empty/error state.
- Быстрое переключение между месяцами не приводит к отображению результата устаревшего запроса.

## Verification

- Открыть Mini App и перейти из марта в апрель.
- Проверить появление loading-state в момент переключения месяца.
- Проверить, что после загрузки отображаются данные именно выбранного месяца.
- Быстро переключить несколько месяцев подряд и убедиться, что итоговый экран соответствует последнему выбору.

## Rollback / Safety

- Rollback должен быть ограничен календарным frontend flow.
- Loading indicator не должен скрывать ошибку или пустой результат после завершения запроса.

## Заметки

- Реализацию выполнять только после отдельного согласования.

  - добавлен request-guard для slots loading
  - добавлен явный loading-state для обновления календаря и времени
