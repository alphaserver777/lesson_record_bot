## Контекст

Сейчас система исходит из базового рабочего графика по дням недели и умеет:

- показывать свободные слоты внутри этого графика
- бронировать часть дня или весь день через admin blocks
- учитывать regular lessons, single bookings и исключения регулярки

Но не хватает обратного сценария: разово расширить доступность на конкретную дату вне основного графика.

Пример:

- основной график не включает обеденное окно
- на конкретную дату появляется незапланированная возможность провести 1-2 урока
- администратор должен иметь возможность добавить это окно в расписание так, чтобы оно стало доступным для записи только на эту дату

Важно: это не регулярка и не изменение базового недельного графика. Это именно разовое расширение доступности на конкретную дату.

## Цель

Добавить в admin flow возможность разово открывать дополнительные слоты на конкретную дату поверх базового графика, не ломая текущую модель расписания и не превращая это в костыль через фальшивые записи или “отрицательные блоки”.

## Scope

В scope:

- ввести отдельную доменную модель разовой дополнительной доступности на дату
- учесть её в расчёте доступных слотов
- добавить admin UI во вкладке расписания для создания и удаления такого окна
- показать эти окна в day view/admin view понятным образом
- обеспечить совместимость с regular lessons, single bookings и admin blocks
- задокументировать source of truth для доступности слотов

Вне scope:

- изменение базового недельного графика
- полноценный редактор weekly schedule
- публичный пользовательский UI для управления дополнительной доступностью
- переработка всей календарной модели за один шаг

## Ограничения

- Нельзя реализовывать это через поддельные booking records.
- Нельзя использовать `block`/`allow` как “обратную” модель открытия слота.
- Разовая дополнительная доступность должна действовать только на одну дату.
- Базовый график по дням недели должен остаться основным источником регулярной доступности.
- Итоговый расчёт слотов должен оставаться предсказуемым:
  базовый график + extra availability - занятые слоты - block/skip/other suppressors.

## Текущее состояние

- Базовая доступность строится из основного графика.
- Есть date-specific suppressors: blocks, allow, regular exceptions.
- Нет отдельной сущности, которая открывает новые слоты вне базового графика на конкретную дату.

## Предлагаемое изменение

### 1. Новая модель

Добавить отдельную таблицу или сущность, например:

- `date_availability_overrides`

Поля первой версии:

- `id`
- `target_date`
- `start_time`
- `end_time`
- `mode` со значением `extra_open`
- `note`
- `created_at`

Смысл:

- базовый график остаётся как есть
- `extra_open` добавляет дополнительное окно доступности только на одну дату

### 2. Логика расчёта доступности

При расчёте доступных слотов на дату:

1. взять базовые интервалы по недельному графику
2. добавить окна `extra_open` для этой даты
3. вычесть занятые слоты, blocks, regular suppressors и другие доменные ограничения

Это должно работать и для Mini App, и для admin day view.

### 3. Admin UI

В `Записи -> Свободные слоты` нужен action рядом с текущим просмотром даты:

- кнопка `Добавить временные слоты`
- дата не вводится отдельно, а берётся из уже выбранного дня в календаре
- `с` / `по`
- комментарий
- кнопка сохранения

Также нужен просмотр уже созданных разовых окон на выбранную дату и их удаление.

### 4. Отображение

В day view/admin view должно быть видно, что это не бронь и не занятие, а именно дополнительное окно доступности на дату.

## Acceptance Criteria

- Администратор может добавить дополнительное окно доступности на уже выбранную в календаре дату.
- Слоты из этого окна становятся доступны для записи, даже если их нет в базовом недельном графике.
- Эти слоты существуют только на выбранную дату и не повторяются.
- Existing blocks, single bookings, regular lessons и exceptions продолжают корректно ограничивать доступность.
- Администратор может увидеть и удалить разовое дополнительное окно.
- Поведение доступности задокументировано как единая доменная модель.

## Verification

- Выбрать дату в календаре, добавить extra availability вне обычного графика и проверить появление новых слотов.
- Записать ученика в один из этих слотов и проверить корректное отображение.
- Поставить block на часть extra availability и проверить, что блок подавляет соответствующий слот.
- Удалить extra availability и проверить, что слоты исчезают.
- Выполнить `python -m compileall database webapi utils handlers`.
- Собрать Mini App.

## Rollback / Safety

- Если вводится новая таблица, нужен понятный rollback path.
- До production rollout с schema change нужен backup БД по принятому процессу.
- Если новая модель ломает расчёт доступности, rollback должен возвращать систему к базовому графику без extra windows.

## Заметки

- Эта задача, вероятно, меняет source of truth для доступности и может потребовать ADR.
- В будущем можно расширить модель до date-specific “close/open override”, но в первой версии нужен только сценарий `extra_open`.
- В текущей реализации entrypoint находится в `Записи -> Свободные слоты`, дата берётся из уже выбранного дня календаря.
- Дополнительные окна хранятся в `date_availability_overrides` с `mode='extra_open'`.
